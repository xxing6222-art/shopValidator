# 勇哥聊天式店铺问诊整合设计

> 状态：已废弃。当前产品已按 `origin/main` 恢复原版问诊交互；本文仅保留为历史设计记录。

日期：2026-07-24

## 目标

修复首页“开始店铺问诊”和“查看诊断示例”的入口可靠性，并将四步业务流程中的第二步“店铺问诊”替换为勇哥聊天式界面。

改版只改变入口路由与问诊呈现层。位置确认、问题规划、语音与文字降级、事实提取、事实纠偏、分析结果、公开案例和排行榜的数据逻辑保持原样。

## 已确认问题

1. “开始店铺问诊”当前由 JavaScript 拦截 `#judge` 链接后切换 `data-product-view`。URL 不记录工作区状态，刷新、脚本异常或直接访问时无法恢复。
2. “查看诊断示例”仍跳转到 `https://demo.yongge.zhangyvjing.com`，该地址当前连接关闭。
3. 现有问诊状态机与 Worker 接口仍可用，不需要重写业务核心。

## 方案选择

采用“保留状态机，替换问诊呈现层”的方案。

- 不采用隐藏旧界面并镜像聊天界面的方案，因为它会产生两套 DOM 状态和焦点管理。
- 不采用重写问诊控制器的方案，因为它会扩大对 API、语音、演示和事实提取链路的影响范围。

## 入口与路由

### 开始店铺问诊

- 首页入口使用本地 `#judge` 地址。
- 初始化时根据 hash 恢复 landing 或 workspace。
- 点击入口时先更新 hash，再进入位置确认面板。
- 浏览器前进、后退和刷新后，工作区状态可预测地恢复。
- JavaScript 未加载时，原生锚点仍能落到问诊区域。

### 查看诊断示例

- 示例入口改为本地 `/?demo=1`，不再依赖外部演示域名。
- 演示继续复用当前 `DEMO_MODE`、案例地图、问诊播放、纠偏和结果生成逻辑。

## 问诊界面

问诊面板改为单一聊天会话容器。

### 顶部栏

- 返回按钮返回位置确认步骤。
- 标题为“勇哥判店”。
- 显示“在线”状态。
- 显示“AI 开店诊断 · 已完成问题数 / 目标问题数”。

### 对话区

- 勇哥问题显示在左侧暖灰色气泡。
- 用户已提交答案显示在右侧蓝色气泡。
- 每个勇哥问题配一个纸片人形象，按对话轮次轮换使用已有素材：
  - `7c1fe4124f7252982044957df0df0652.png`
  - `纸片人统一版-01-整理衣领.png`
  - `纸片人统一版-02-双手合拢.png`
  - `纸片人统一版-03-指示动作.png`
  - `纸片人统一版-04-抱臂思考.png`
- 对话记录来自当前会话中的真实问题与已提交答案，不复制一套业务状态。
- 新消息出现后滚动到末尾；历史消息可回看。

### 输入区

- 保留文本输入、语音输入、发送、上一题和演示填充能力。
- 文字发送继续调用现有 `confirmAnswerDraft()`。
- 语音识别结果继续写入现有答案草稿，不改变 ASR 接口。
- 发送中禁用重复提交，并显示明确状态。
- 语音不可用、权限拒绝或服务异常时，自动回退到文字输入。

### 响应式

- 桌面端聊天主体居中，最大宽度约 520px，置于现有纸张风格工作区中。
- 移动端聊天主体占满可用宽度，输入栏固定在面板底部。
- 不模拟手机外壳、系统状态栏或灵动岛。

## 业务数据流

```text
位置确认
  -> beginInterview()
  -> askQuestion() / 服务端 nextQuestion
  -> 聊天区追加勇哥问题
  -> 用户输入或语音转写
  -> confirmAnswerDraft()
  -> 本地 fact 提取或 POST /api/cases/:id/turns
  -> 聊天区追加用户答案
  -> 下一问题或 finishInterview()
  -> 事实纠偏
  -> 确定性分析与结果
```

问诊聊天层只订阅和展示上述状态变化，不直接计算事实、不决定下一问题，也不绕过 review 步骤。

## 组件边界

### 保留

- `beginInterview`
- `askQuestion`
- `confirmAnswerDraft`
- `submitRemoteTurn`
- `startDemoInterview`
- `finishInterview`
- `interview-policy.js`
- Worker 的 case、turn、review、analysis API

### 新增或调整

- 本地入口/hash 同步函数。
- 问诊消息渲染函数。
- 当前问题、答案提交与聊天记录之间的单向同步。
- 问诊专属 HTML 结构和响应式样式。
- 纸片人静态资源纳入构建白名单。

## 异常处理

- 外部示例站不可用：彻底移除该依赖，使用本地 demo。
- 问诊建档失败：沿用现有本地问诊降级，并在勇哥气泡中显示降级说明。
- ASR 不可用：输入区保持可编辑，状态栏提示已切换文字模式。
- 远程提交失败：保留当前答案，不重复插入用户气泡，允许再次发送或结束问诊。
- 返回上一题：复用现有回退逻辑，并同步移除或标记最后一轮聊天显示，避免视觉记录与事实状态不一致。

## 测试与验收

### 自动化

1. 首页开始入口可进入位置步骤，hash 可恢复。
2. 示例入口指向本地 `?demo=1`。
3. 完成位置确认后进入聊天式问诊。
4. 当前问题显示为勇哥气泡。
5. 用户提交答案后只追加一次用户气泡，并出现下一道勇哥问题。
6. 上一题、文字降级、演示播放和完成问诊仍可用。
7. 纠偏、分析、结果和排行榜现有回归测试继续通过。

### 浏览器验收

- 桌面和 390px 移动视口均无横向滚动。
- 两个首页入口均可真实点击。
- 完整 demo 可从入口走到结果页。
- 真实问诊在无地图或语音 secret 时仍能以现有降级路径继续。
- 控制台无未处理异常，关键按钮没有被样式层遮挡。

## 非目标

- 不改变问题数量、问题顺序和完成条件。
- 不修改事实字段、决策规则、结果算法或 Worker 数据模型。
- 不新增登录、持久化聊天历史或第三方聊天服务。
- 不重做位置、纠偏、结果和排行榜页面。
